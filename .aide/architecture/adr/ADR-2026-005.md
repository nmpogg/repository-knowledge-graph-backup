# Versioned analyzer adapter boundary

## Context

MVP cần ship Python/FastAPI trước nhưng product phải bổ sung ngôn ngữ/framework khác
mà không fork coordinator, graph store hoặc transport API.

## Decision

1. Core analyzer chỉ phụ thuộc `LanguageAdapter` và `FrameworkAdapter` contracts cùng
   các DTO chung: immutable manifest, parsed unit, symbol index, `FactBatch`,
   diagnostic và capability report.
2. Adapter được chọn từ `REG-ADAPTER-001` theo ID/version/language compatibility và
   evidence detection. Core không dùng branch theo tên Python/FastAPI hay adapter ID.
3. Language adapter sở hữu grammar target, file discovery/ignore convention, parsing
   và language-level resolution. Framework/deep adapter sở hữu pattern cụ thể và chỉ
   chạy trên parsed units của language tương thích.
4. GraphValidator và publisher chỉ nhận generic `FactBatch`; adapter không được ghi
   Kùzu, gọi network, thực thi source hoặc thay đổi job/snapshot lifecycle.
5. Contract được version hóa. Incompatible contract change cần version mới; adapter
   không tương thích được báo capability/diagnostic thay vì được nạp ngầm.
6. Python 3.12/FastAPI/SQLAlchemy 2.x/aiokafka là adapter set đầu tiên. Một conformance
   fixture adapter độc lập phải chứng minh registration/indexing không sửa core,
   schema hoặc API.

## Consequences

Core có thêm abstraction và conformance suite từ đầu, đổi lại adapter mới có boundary,
failure semantics và evidence rules nhất quán. Semantic graph type mới vẫn cần schema
change riêng; adapter contract không được dùng để lách schema governance.

## Rejected

- Branch theo language/framework trong coordinator: nhanh cho adapter đầu tiên nhưng
  làm chi phí adapter sau tăng theo số tích hợp.
- Plugin chạy code tùy ý ngoài process: tăng isolation/packaging complexity và không
  cần thiết cho MVP local; có thể đánh giá bằng ADR riêng sau.
