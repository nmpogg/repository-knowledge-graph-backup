# Repository catalog with immutable snapshots

## Context and criteria

The source-form model can index and explore one workspace but cannot safely return
to a registered repository, enumerate its history or express ownership for lifecycle
operations. A separate RepositoryVersion entity would duplicate Snapshot identity in
the MVP because every index result already records the exact source revision and
analysis configuration.

## Options considered

1. Persistent Repository catalog with `Repository 1 — N Snapshot`.
2. Repository → RepositoryVersion → Snapshot.
3. Keep an unowned global snapshot history and client-side active selection.

## Decision

Choose option 1. Repository is the persistent aggregate root for one immutable source
identity. Snapshot is the immutable indexed version and stores source revision,
manifest/config digests and tool versions. There is no RepositoryVersion entity.
The application may register multiple repositories, but graph reads and conversations
are always scoped to exactly one repository/snapshot; cross-repository graph and
analysis remain out of scope.

Each repository owns its active snapshot pointer. Index success creates a new
snapshot and atomically moves that pointer; explicit activation may point it to an
older retained snapshot without re-indexing. Source identity is immutable because
changing it under an existing repository would make historical snapshot ownership
misleading.

## Consequences and guardrails

- Repository PATCH uses optimistic revision and changes metadata/defaults only.
- Snapshot has no graph/source PATCH. Re-index always creates a new snapshot.
- Snapshot delete is blocked for active/read/pinned snapshots. Repository delete is
  additionally blocked by non-terminal jobs and cascades only unreferenced owned data.
- One application-wide index writer remains the MVP rule; multi-repository catalog
  does not imply parallel writers or cross-repository graph.
- API routes make repository ownership explicit; mismatched identifiers return a
  non-disclosing not-found response.
