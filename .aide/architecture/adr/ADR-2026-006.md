# ADR-2026-006 - Directory structure and language scope metadata

## Context

Python Namespace nodes often duplicate the file/module identity already represented
by SourceUnit. Users need a filesystem structure that applies across languages.
A directory and a language namespace are different concepts: Java packages can
span files and need not be inferred directly from filesystem paths.

## Decision

1. The logical types are Repository, Directory, SourceUnit, Type, Callable,
   Endpoint, DataResource, MessageChannel, Configuration and ExternalDependency.
2. Repository lifecycle owns the root. Core constructs Directory ancestors from
   emitted manifest-backed SourceUnits without a second filesystem traversal.
   Adapters own source units, syntax, qualified identities, lexical containment,
   semantic relations, evidence and limitations.
3. New snapshots do not emit Namespace. Module/package scope remains in symbol
   resolution and SourceUnit metadata (`module_name`/`package_name`), preserving
   language-native qualified names. Resource namespace fields stay unchanged.
4. Directory path, ID, containment and path-provenance evidence follow the current
   storage contract, `TBL-RKG-GRAPH` revision 12. The decision was first written
   against revision 10. Revisions 11 and 12 carry that contract forward; revision
   12 adds no tables. Root is Repository, not a duplicate Directory; no empty
   folders. Revision 1 of this ADR named only revision 10.
5. API and UI expose Directory consistently in search, Graph, List and Structure.
   The UI reuses API identity instead of creating duplicate directory nodes.
6. Transition new indexing to adapter contract rkg.adapter/v2. Explicit compatibility
   retains old Namespace snapshots and conversation references; never rename or
   rewrite historic graph facts. A versioned migration extends physical CONTAINS
   to Repository -> Entity while preserving Entity -> Entity relationships.
7. Documentation was prepared before code. The user confirmed code work on
   2026-10-01 and `TASK-RKG-027` is done. Revision 1 said the task remained todo
   until that confirmation. This ADR stays `draft`. No gate approval is inferred
   from the completed task.

## Consequences and verification

Simpler source structure comes at the cost of losing direct namespace-node queries.
Module/package semantics still require adapter resolution; filesystem paths cannot
replace them. Existing fixtures, adapter conformance, structural evidence handling,
physical relationships, API types and frontend views require coordinated updates.
Validate root/nested/empty files, duplicate basenames, source_root scans, ignored or
unparsed source, stable IDs, no import target Directory, migration/history retention
and mixed-language conformance without running analyzed source. Java implementation
is outside this change; Java examples only describe the extensible contract.

## Alternatives

- Keep Namespace and add Directory: preserves scope nodes but retains the duplicate
  Python module/file presentation the user asked to remove.
- Rename Namespace to Directory: rejected because namespace identities and directory
  paths are semantically different and historical snapshots must stay immutable.
- Synthesize directories only in UI: rejected because directories need real graph
  identity for search, traversal, selection and context.
