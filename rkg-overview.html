Repository Knowledge Graph

Biến một thư mục source trên máy thành graph kiến trúc có bằng chứng. Developer duyệt sơ đồ và hỏi đáp kèm citation. Agent dùng cùng snapshot làm context.

Local-first · một repository · snapshot bất biến

01 — Bối cảnh

Vấn đề cần giải

Lần luồng thủ công

Nắm endpoint → handler → service → DB / event phải mở nhiều file, dễ sót quan hệ có hướng.

Search chưa đủ kiến trúc

IDE tìm symbol tốt, nhưng khó trả lời: API này ghi bảng nào, ai publish topic, sửa entity này ảnh hưởng gì.

Công cụ lớn thì nặng

Nền tảng code intelligence quy mô enterprise khó áp cho một repo local, một người dùng.

Agent thiếu grounding

Đưa nguyên source làm context dễ quá lớn và dễ bịa khi không có quan hệ, evidence và giới hạn rõ.

02 — Người dùng

Ba nhóm dùng cùng một graph

Developer mới

Cần tìm endpoint, xem handler và mở đúng vị trí source khi mới vào dự án.

Maintainer

Cần subgraph có hướng: caller, đọc/ghi dữ liệu, publisher và consumer, kèm bằng chứng.

AI agent

Cần JSON entity, quan hệ và vị trí theo snapshot, trong một ngân sách context cố định.

Mục tiêu: giảm thời gian hiểu codebase, trả lời câu hỏi kiến trúc nhanh hơn, và giữ câu trả lời bám graph kể cả khi tắt LLM.

03 — Sản phẩm

Ba việc trên một snapshot

Index

Quét thư mục local, nhận diện stack qua adapter, trích entity và cạnh có rule cùng vị trí source. Kết quả là snapshot không sửa được.

Duyệt

Search, Explorer và context JSON trên snapshot đang active. Phần này chạy khi không có LLM.

Hỏi đáp

Hội thoại tiếng Việt hoặc Anh, nhiều lượt, citation từ graph. Provider là OpenAI hoặc OpenRouter, cấu hình phía server.

05 — Cách làm

Các lớp chính

Giao diệnReact và Vite: danh sách repository, theo dõi job, Explorer, hội thoại.
API localPython, CLI rkg và server chỉ bind 127.0.0.1. UI và CLI dùng cùng contract.
Phân tíchAdapter theo ngôn ngữ và framework. Fact resolve được phải có rule và evidence. Pattern ngoài contract chỉ được ghi nhận, không đoán cạnh.
GraphKùzu nhúng. Entity trung lập: thư mục, file, type, callable, endpoint, data, message, config, dependency ngoài.

06 — Phạm vi

Trong bản này làm gì

Có

  • Catalog repository local, nhiều snapshot, activate và xóa có chặn tham chiếu.
  • Full rebuild, báo cáo scan, diagnostic theo file.
  • Search, duyệt subgraph, context JSON, Graph Explorer.
  • Hỏi đáp có citation; search và graph vẫn chạy khi LLM tắt.

Chưa làm

  • Clone từ Git URL, index tăng dần, graph xuyên nhiều repository.
  • Đọc giá trị config, secret, hoặc suy URL động.
  • Vector DB, để LLM tự tạo fact trên graph, hay agent tự sửa code.
  • SSO, multi-tenant, triển khai public.

07 — Ràng buộc

Cách chạy an toàn

Source chỉ để đọc

Không import, không cài dependency, không build và không thực thi mã của repository được phân tích.

Đường dẫn bị giới hạn

Chỉ quét trong --allow-root. Symlink thoát gốc bị từ chối. Giới hạn số file và kích thước file.

Một người, trên máy

Server loopback, một worker. Session token cho thao tác ghi và lấy context.

Log không lộ nội dung

Không ghi đường dẫn tuyệt đối, secret, source thô hay transcript vào log vận hành.

08 — Evaluation

Ba chỉ số nghiệm thu

Trích xuất fixture

So fact canonical với expected JSON trên toàn bộ golden fixture. Coverage = TP / (TP + FN), precision = TP / (TP + FP). Đạt khi cả hai bằng 100%.

Độ chính xác cạnh trên pilot

Chấm từng nhóm cạnh: import, call, DI, DB, event, config, implements. Mỗi nhóm công bố phải ≥ 95%. Thiếu mẫu thì ghi không đủ mẫu, không gộp nhóm để cho qua.

Hỏi đáp bám graph

Bộ câu có đáp án, câu thiếu dữ liệu, câu mơ hồ, câu injection và hội thoại nhiều lượt. Accuracy ≥ 90%. Citation phải đủ và đúng. Không có claim trái graph.

Đổi fixture, rubric hoặc cách đo thì tăng revision. Kết quả cũ giữ nguyên, không ghi đè.
